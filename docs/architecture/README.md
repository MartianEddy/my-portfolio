# Architecture documentation

This directory contains system-level architecture descriptions, component boundaries, data-flow documentation and security architecture notes.

## Documentation expectations

For each material system, document:

- purpose and non-goals;
- components and responsibilities;
- data flows and trust boundaries;
- identities, permissions and secrets;
- failure modes and operational assumptions;
- security controls and residual risks;
- verification evidence and known limitations.

Architecture documents must describe the implementation that exists, not an aspirational design as though it were already deployed. Proposed capabilities should be labelled accordingly.
